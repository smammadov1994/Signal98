# signal98

Capture SDK for [signal98](../README.md): errors, failed requests, logs, pageviews, clicks, rage and dead clicks,
web vitals, sessions, identity and feature flags — from browsers and Node. Zero runtime dependencies,
~11.5 KB gzipped as a script tag. Events are **judged at ingest by JEV**, so what pages you is a rule over
meaning (severity, user-facing, your code, revenue…), not a count.

It will never throw into your app: every hook, patch and transport path swallows its own failures, and
calling anything before `init()` is a quiet no-op.

## Install

**Script tag**

```html
<script src="https://YOUR-SIGNAL98-HOST/s98.js" data-key="YOUR_PROJECT_KEY" data-host="https://YOUR-SIGNAL98-HOST" defer></script>
```

Optional attributes: `data-environment`, `data-release`, `data-service`. The global is `window.signal98`.
To call it before the script has loaded, queue:

```html
<script>window.signal98 = window.signal98 || { _q: [] }; signal98._q.push(["capture", "landing_seen", { variant: "b" }]);</script>
```

**npm**

```bash
npm install "http://localhost:3001/downloads/signal98-0.2.0.tgz"
```

```js
import { init } from "signal98";

init({ host: "https://YOUR-SIGNAL98-HOST", apiKey: "YOUR_PROJECT_KEY", release: "web@1.4.2" });
```

Get YOUR_PROJECT_KEY from your Signal98 monitor’s setup walkthrough or Settings → Connect your app. This public capture key is generated by Signal98; it is not your private TypeSafe/JEV key. The install URL serves the SDK built by your running monitor; replace localhost with its address. See the root README for full React and Next.js setup.

That is the basic integration. Uncaught errors, unhandled rejections, pageviews (History API aware), clicks,
rage/dead clicks, web vitals and failed or slow `fetch`/XHR requests are captured automatically.

## API

| call | what it does |
|---|---|
| `init(options)` | start. Idempotent. |
| `capture(event, props)` | a product event: `capture("order_completed", { total: 4200 })` |
| `captureException(err, props)` | report a caught error (type, message, parsed stack, `error.cause` chain, fingerprint, breadcrumbs) |
| `wrap(fn, { name })` | returns `fn` that reports what it throws (sync or async) and rethrows |
| `addStep(message, props)` | breadcrumb attached to the next exception |
| `identify(id, $set, $set_once)` | tie this browser to a user; earlier anonymous activity is folded in server-side |
| `reset()` | on logout: fresh anonymous id and session |
| `register(props)` / `unregister(key)` | super-properties sent with every event |
| `log.debug/info/warn/error(msg, props)` | `$log` events; `error` level opens an issue |
| `isFeatureEnabled(key)` / `getFeatureFlag(key)` / `onFeatureFlags(cb)` / `reloadFeatureFlags()` | flags, bucketed stably per user, cached locally |
| `getDistinctId()` / `getSessionId()` | current ids |
| `flush()` / `close()` | send now / unhook everything and send |

### Options

| option | default | |
|---|---|---|
| `host` | — | base URL of your signal98 server (`endpoint` = full ingest URL, legacy) |
| `apiKey` | — | project key from Control Panel → Install |
| `service` / `release` / `environment` | host name / — / `production` | attached to every event |
| `sampleRate` | `1` | fraction of events kept |
| `beforeSend(event)` | — | mutate, or return `null` to drop. A throwing hook is ignored |
| `ignoreErrors` | — | strings / RegExps matched against `Type: message` |
| `flushInterval` / `flushAt` / `maxQueue` | `3000` ms / `20` / `500` | batching. Exceptions and rage clicks flush immediately |
| `slowRequestMs` | `4000` | slower requests are reported with `$slow: true` |
| `persistence` | `"localStorage"` | or `"memory"`. The unsent queue survives reloads and offline |
| `respectDNT` | `false` | capture nothing under Do Not Track |
| `autoCapture` | all on except `console` | `{ errors, rejections, console, steps, pageviews, clicks, rageClicks, deadClicks, webVitals, network }`, or `false` |
| `debug` | `false` | log SDK internals |

Delivery: `fetch` with `keepalive`; `sendBeacon` only while the page is being hidden. Network failures, `429` and
`5xx` retry with exponential backoff and jitter (honouring `Retry-After`); other `4xx` drop the batch.
An error thrown in a tight loop is limited to 10 reports per fingerprint per 10 s.

### Privacy

Input values are never captured. Text inside `data-s98-mask` / `.s98-mask` becomes `***`; `data-s98-ignore`
skips an element entirely. Query strings are stripped from URLs in network events.

### React

```jsx
import { init, getClient } from "signal98";
import { createErrorBoundary } from "signal98/react";

init({ host, apiKey });
const SignalBoundary = createErrorBoundary(getClient());

<SignalBoundary fallback={<p>Something broke.</p>}><App /></SignalBoundary>;
```

### Node / Express

```js
import { init, requestHandler, errorHandler } from "signal98";

init({ host, apiKey, service: "api" });   // uncaughtException + unhandledRejection are hooked
app.use(requestHandler());                 // first: one breadcrumb per request
// …routes…
app.use(errorHandler());                   // last: reports 5xx, then passes the error on
```
